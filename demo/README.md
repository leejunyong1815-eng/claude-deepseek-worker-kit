# 랩미팅 데모: 연구 작업을 로컬 LLM에 위임하고 검증하기

사용자는 연구 목표를 말하고, Claude 오케스트레이터가 두 로컬 LLM 워커에 구현을 나눠 맡긴다.
각 워커의 독립 worktree와 외부 검증을 확인한 뒤, **현재 컴퓨터의 로컬 CPU**에서 작은 실험을 돌려 보고서를 만든다.
WSL2를 기본 사용 환경으로 가정한다. LLM 서버는 추론만 담당하며 계산 backend와 별개다.

참고한 대화는 **「qcfd 로컬 LLM 서브에이전트 벤치마크」**다. 연구 재현, 커버리지와 완성도의 구분,
독립 검증이라는 흐름을 축소했다. 이 데모는 원래 QCFD 실험이나 원본 결과를 재현·채점하는 벤치마크가 아니다.
범위와 참고 내역은 [SOURCE_NOTES.md](SOURCE_NOTES.md)에 있다.

일반 운영은 계약 기반 모듈 구현을 로컬 워커에 먼저 맡긴다. 이 데모는 발표 시간을 줄이기 위해
실험 하네스·테스트를 미리 제공하고 두 함수만 위임한다. 데모의 호출량을 일반 프로젝트의 위임 비율로 해석하지 않는다.

## 무엇을 보여 주나

| 단계 | 화면에서 확인할 것 |
|---|---|
| 사용자 요청 | 아래 프롬프트 하나로 시작. 사용자가 워커 이름·task ID·명세를 작성하지 않음 |
| 두 구현 위임 | A: 선형계 행 스케일링, B: 샷 표본의 확률분포 충실도. 각각 별도 worktree |
| 외부 검증 | 보호된 unittest와 허용 경로 검사. 워커의 “완료” 문구로 성공 처리하지 않음 |
| 로컬 실험 | 4×4·6×6 Poisson 이산 행렬, 고정 시드 샷 표본. Python 표준 라이브러리만 사용 |
| 결과 | task/attempt ID, 검증·변경 파일, 수치와 입력 해시를 담은 `report.html`, `results.json`, `REPORT.md` |

조건수는 **무한대 노름 조건수 κ∞**, 샷 지표는 **확률분포 충실도**다. 부호·위상을 검증하는 양자 상태 충실도가 아니다.
QPU·원격 GPU·원본 연구 저장소·원격 계산 노드는 사용하지 않는다.

## 1. 키트 설치

키트 저장소에서 실행한다.

```bash
./install.sh
```

LLM 서버·모델은 연구실 설정을 사용하고, 원격 계산 노드 질문은 Enter로 비워 둔다.
구현 프로필 `impl`을 만들면 데모가 이를 선택하며, 없으면 기본 프로필을 사용한다.
기존 설정은 설치기가 보존한다. 이미 원격 호스트가 설정되어 있어도 이 데모의 계산과 검증은 로컬 CPU로 지정된다.
새 패키지 설치나 NumPy·Qiskit·GPU 드라이버 설정은 필요하지 않다.

실제 서버 연결을 미리 확인하려면 `llm-probe`를 사용한다. 이 프로브는 모델 요청을 보낸다.
먼저 Claude 로그인과 프로젝트 권한을 확인한다. 데모는 권한 우회 옵션을 자동으로 붙이지 않는다.

## 2. 새 데모 작업 공간 준비

```bash
python3 -B demo/prepare.py
```

이 명령은 `/tmp/local-llm-lab-…/project`에 새 Git 저장소를 만들고 스켈레톤·테스트·태스크 입력을 기준 커밋으로 저장한다.
기존 키트와 QCFD 저장소는 바꾸지 않는다. 준비 단계에서는 모델을 호출하지 않는다.
출력된 실제 경로로 이동해 오케스트레이터를 시작한다.

```bash
# prepare.py가 출력한 경로로 이동한 뒤 실행한다.
./start.sh
```

`start.sh`는 준비된 작업 공간으로 이동해 `claude-main --model claude-fable-5-1 --effort high`를 실행하고
데모 운영 지침을 추가한다. 참고 대화에서 선택한 Fable 오케스트레이터를 사용한다.
계정에서 다른 모델을 사용해야 한다면 `DEMO_ORCHESTRATOR_MODEL=<사용할 모델> ./start.sh`로 명시한다.
오케스트레이터 이름은 실행마다 고유하게 정하며 워커 모델 라우팅은 바꾸지 않는다.

경로를 직접 지정할 수도 있다. 기존 경로는 덮어쓰지 않는다.

```bash
python3 -B demo/prepare.py --workspace /tmp/my-fresh-lab-demo
```

## 3. 실행 후 붙여 넣을 프롬프트

**[PROMPT.md](PROMPT.md) 전체를 오케스트레이터 창에 붙여 넣는다.** 작업 공간에도 같은 파일이 복사된다.
기본 요청은 “두 구현을 로컬 워커에 나눠 맡기고, 검증한 뒤 로컬 실험·보고서까지 만들어 줘”다.
워커를 직접 부르거나 사용자가 관리 CLI를 입력할 필요는 없다.

스켈레톤 테스트는 시작할 때 실패하도록 준비되어 있다. 오케스트레이터는 테스트를 바꾸거나 직접 답을 채우는 대신
두 워커의 구현을 기다린다. 실패하면 로그를 검토하고 시도를 보존하며, 두 번 실패한 태스크는 미완료로 보고한다.
두 태스크가 검증된 뒤에만 `tools/finish.py`로 구현을 불러온다. 원래 체크아웃으로 코드를 복사·merge할 필요가 없다.

## 4. 랩미팅에서 보여 줄 순서

진행 멘트와 체크포인트는 [RUNBOOK.md](RUNBOOK.md)를 따른다.

1. 오케스트레이터에게 목표를 한 번 전달한다.
2. 두 task ID, 서로 다른 worktree와 실행 상태를 보여 준다.
3. 워커가 끝나도 외부 검증을 거쳐야 `succeeded`가 되는 것을 설명한다.
4. 보고된 `report.html`을 브라우저로 연다. WSL 경로는 필요하면 `wslpath -w`로 Windows 경로로 변환한다.
5. 행 스케일링 전후 κ∞·잔차, 샷별 분포 충실도, 원시 결과와 로그 경로를 확인한다.

두 구현이 빠르더라도 생성 지연과 권한 확인에 따라 발표 시간이 달라진다. 발표 전 실제 설정으로 작은 리허설을 권장한다.
실행 중인 대화가 정상이라도 실제 워커 호출·외부 검증·완성된 보고서가 없으면 성공 데모로 설명하지 않는다.

## 서버 없이 리허설

```bash
python3 -B demo/rehearse.py
```

실제 `worker-task`·Git worktree·테스트·보고서 생성을 사용하되 `claude`만 모의 실행기로 대체한다.
모의 실행기는 `reference/`의 짧은 예제 구현을 복사한다. 이 해답은 live 작업 공간에 복사하지 않는다.
HTML 상단에 **OFFLINE REHEARSAL**을 표시하므로 실제 LLM이 구현한 결과와 구별할 수 있다.
모델·서버 연결, 실제 권한 설정, 성능·토큰 절감은 이 리허설로 검증하지 않는다.

생성된 프로젝트·워크트리·상태·로그·보고서는 보존된다. 다시 실행하면 새 작업 공간을 사용한다.
회귀 검사는 `python3 -B -m unittest discover -s demo/tests -v`로 실행한다.

## 파일 구성

```text
prepare.py               새 작업 공간과 입력 기준 커밋 준비
PROMPT.md                실행 후 사용자가 붙여 넣을 요청
DEMO_ORCHESTRATOR.md     로컬 CPU·분업·검증·완료 보고 규칙
fixture/                 스켈레톤 2개, 보호된 테스트, 작은 실험 입력·하네스
finish.py                검증된 두 구현을 불러와 JSON·Markdown·HTML 생성
rehearse.py               서버 없이 전체 실행 경로 점검
reference/               모의 실행기 전용 해답; live 입력에서 제외
tests/                   준비·외부 검증·보고서 무결성 회귀 검사
RUNBOOK.md               발표자 진행 메모
SOURCE_NOTES.md          참고 대화와 데모의 차이
```
