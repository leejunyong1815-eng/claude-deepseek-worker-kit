# 랩미팅 진행 메모

## 시작 전에

실제 발표 환경은 Linux/WSL2, Python·Git·설치된 Claude CLI와 로그인, 연구실 LLM 설정이다.
계산 backend는 로컬 CPU다. QPU나 별도 원격 GPU 계정은 필요하지 않다.
LLM 추론 서버의 모델·라우팅을 바꾸지 않는다. Qwen이 GB10에서 서비스되는지는 서버 설정 사항이며 이 데모가 배포 위치를 측정하지는 않는다.

`prepare.py`로 발표 전용 새 작업 공간을 만들고 `start.sh`로 Fable 오케스트레이터를 연다.
필요한 파일 편집·명령 실행 권한은 발표 전에 사용자가 확인한다. 권한 질문이 나오면 내용을 확인하고 결정한다.
실제 모델 리허설에는 모델 요청이 발생하며, offline 리허설과 구분해서 기록한다.

## 도입

“사용자는 연구 목표만 말합니다. Claude가 설계와 작업 분해를 맡고, 실제 구현은 연구실 로컬 LLM에 넘깁니다.
오늘은 전체 QCFD 연구를 반복하는 대신, 전처리와 샷 읽기 지표의 작은 구현 두 개로 실행 흐름을 보겠습니다.”

`PROMPT.md`를 한 번 붙여 넣는다. 태스크 등록과 워커 이름을 사용자가 입력하는 장면은 기본 시연에서 생략한다.

## 구현 중

“두 작업은 서로 독립적이라 다른 워커가 각자의 worktree에서 구현할 수 있습니다.
원래 체크아웃에는 테스트와 스켈레톤이 남고, 각 구현은 별도 작업 공간에 쌓입니다.”

오케스트레이터에게 “현재 두 task ID와 작업 경로, 실행 상태를 보여 줘”라고 요청한다.
경로가 다르고 검증 명령이 각 태스크에 고정되어 있는지 확인한다. 서버 여건상 순차 실행했다면 병렬로 실행했다고 말하지 않는다.

## 검증 후

“워커가 ‘완료’라고 답해도 끝이 아닙니다. 실행기가 보호된 파일과 수정 범위를 확인하고,
별도 테스트의 실제 종료 코드를 확인합니다. 그 뒤에 검증된 코드로 작은 계산을 돌립니다.”

두 태스크의 `verification_valid`와 `artifacts_complete`, 검증 종료 코드를 확인한다.
`report.html`에서는 다음을 짚는다.

- 커버리지 2/2는 이 데모의 두 모듈에 대한 수치다. 전체 연구 재현율이 아니다.
- κ∞ 감소를 보기 전에 잔차와 같은 해를 유지했는지를 본다. 행 크기 불균형을 인위적으로 준 입력이다.
- 샷을 늘렸을 때 분포 충실도의 관측값을 본다. 시드별 값은 원시 JSON에 있다.
- 분포 충실도는 부호·위상을 평가하지 않으므로 양자 상태 충실도라고 부르지 않는다.
- 시간은 작은 로컬 수치 실험에 걸린 값이다. LLM 생성 시간이나 모델 간 속도 비교가 아니다.

## 마무리

“핵심은 모델이 만든 코드의 양보다 위임·격리·검증·근거가 남는 실행 흐름입니다.
QCFD 전체 재현이나 모델 성능 비교는 별도의 실험 설계와 반복 실행이 필요합니다.”

실패했다면 실패한 태스크·이유·로그를 그대로 보여 준다. 두 번 실패했는데 Claude가 직접 채운 코드를 로컬 LLM 성과로 표시하지 않는다.
서버 문제로 offline 리허설 보고서를 대신 열 때는 상단 **OFFLINE REHEARSAL**을 보여 주고 모의 실행임을 먼저 설명한다.
